# Phase 06.03 — Form Builder: Create & Edit Pages

## Goal

Wire everything together into two full pages: `/forms/new` (create) and `/forms/[id]/edit` (edit). Both share the same editing UI and AI integration. The edit page additionally loads existing form data and offers delete.

---

## 1. Create page (`/forms/new`)

### State

```ts
title: string                // "Untitled Form" default
description: string          // ""
questions: FormQuestionInput[]  // starts with 1 blank question
conversationId: string | null
formId: string | null
saving: boolean
aiGenerating: boolean
```

### On mount

- Initializes with default title, empty description, one blank question of type "text"

### Actions

**Save** — Calls `createForm()` if `formId` is null, else `updateForm()`. Shows success toast via `sonner`. Stays on page.

**Publish** — Same as save but with `is_published: true`. Shows "Published!" toast. Stays on page. Disabled or labeled differently than save to distinguish intent.

**AI prompt** — Sends prompt + current state + edit summary to `generateQuestions()`. On success: updates questions, title, description, conversationId.

**Add question** — Appends a blank question. Each question needs a unique `id` (counter-based).

**Delete question** — Removes from array. Minimum 1 enforced.

### Layout

```
┌─────────────────────────────────────────────┐
│ [←]               [Unsaved] [Save] [Publish]│
├─────────────────────────────────────────────┤
│ [Form title...............................]  │
│ [Form description........................]   │
│                                             │
│ ─── Questions ────────────────────────       │
│                                             │
│ ┌─ Question 1 ──────────────────────────┐   │
│ │ (question editing UI)                  │   │
│ └───────────────────────────────────────┘   │
│                                             │
│ [+ Add question]                            │
│                                             │
├─────────────────────────────────────────────┤
│  ╔═══════════════════════════════════════╗   │
│  ║ (AI prompt bar)                       ║   │
│  ╚═══════════════════════════════════════╝   │
└─────────────────────────────────────────────┘
```

## 2. Edit page (`/forms/[id]/edit`)

### Additional state

```ts
loading: boolean
loadError: string | null
isPublished: boolean
```

### On mount

- Requires `session.accessToken`
- Calls `getForm(token, id)` to fetch form data
- Populates: title, description, questions, isPublished, conversationId
- Initializes idCounter from existing question IDs

### Same capabilities as create page

- All editing UI
- AI prompt with conversation
- Save with toast
- Publish with toast

### Additional actions

**Delete** — Opens confirmation dialog ("This will permanently delete this form and all its responses. This action cannot be undone.") → calls `deleteForm()` → redirects to `/dashboard`.

### Layout

```
┌─────────────────────────────────────────────┐
│ [←]  [Unsaved] [Save] [Publish] [⋮ Delete] │
├─────────────────────────────────────────────┤
│  (same as create page)                       │
└─────────────────────────────────────────────┘
```

---

## 3. Shared logic

Both pages share these behaviors:

- **Session check**: redirect to login if no `accessToken`
- **Save**: calls create or update API, shows toast, no redirect
- **Publish**: saves with `is_published: true`, shows "Published!" toast, no redirect
- **AI generation**: sends prompt + diff summary, updates state on response, catches 429 with error toast
- **Save indicator**: shows "Unsaved changes" when dirty, "Saving..." during request, "Saved" on success (auto-clears)

---

## 4. Error states

- **Form load failure** (edit page): show error message + "Back to dashboard" link
- **Save failure**: toast with error message, user can retry manually
- **AI failure**: toast with error message
- **Rate limiting (429)**: show error toast, disable AI bar until cooldown expires
