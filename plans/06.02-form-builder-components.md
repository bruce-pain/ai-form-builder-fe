# Phase 06.02 — Form Builder: Core Editing UI

## Goal

Build the interactive UI elements for the form editor. This phase covers all editing surfaces — the user must be able to create and modify every aspect of a form.

No page integration yet (that's 06.03). Build these so they can be composed on both the create and edit pages.

---

## Functional Requirements

### Title & description editing

- Show the current title and description as styled text (not inputs) by default
- Clicking either one switches it to an editable input (single-line for title) or textarea (multi-line for description)
- While editing: Enter confirms, Escape cancels, clicking away (blur) commits the change
- When empty, show a placeholder hint
- The title should be visibly larger / more prominent than the description

### Question editing (per-question)

Each question is rendered as a distinct card/block and provides:

**Question number / index** — Displayed as "Question 1", "Question 2", etc. Visually clear, not just a numeric label.

**Question text** — An auto-resizing textarea. Grows as the user types. Placeholder text when empty.

**Answer type selector** — A control to switch between "text" (free-text answer) and "select" (choose from options). Switching to "text" clears any select-specific data. Switching to "select" initializes an empty options list.

**Required toggle** — A switch/checkbox that marks the question as required. Works for both answer types.

**Select options** (only visible when type=select):
- List of current options, each with a remove (×) button
- Inline input + button to add a new option (pressing Enter also adds)
- A toggle for "Allow multiple selections" (enables multi-select behavior)

**Delete button** — Removes the question from the list. Hidden or disabled when only one question remains (minimum 1).

### Add question action

- A button (styled as outlined/dashed to feel secondary) at the bottom of the question list
- Appends a new blank question with default type "text"

### AI prompt bar

- Fixed to the bottom of the viewport so it's always accessible
- Centered horizontally, with a max width so it doesn't stretch too wide on large screens
- Contains an auto-resizing textarea for typing prompts and a send button
- Send button: visible as an icon (arrow up), circular, positioned on the right side of the input
- Inserting a newline requires Shift+Enter; plain Enter submits
- While generating: send button shows a loading spinner, textarea is disabled
- When rate-limited: textarea is disabled with a message showing cooldown status
- Has a chat-style appearance — rounded container, subtle shadow, slight backdrop blur

### Save indicator

- A subtle text label in the page header area showing the save state
- States: "Unsaved changes" (after an edit), "Saving..." (during save request), "Saved" (after successful save)
- "Saved" auto-clears after a few seconds
